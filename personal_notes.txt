================================================================
NOTE: expanding ChRDispersionOpt to resume WITHIN a design
      (sim-level / ticket-level resume)
================================================================

GOAL
----
Today, resume is at DESIGN granularity (inherited from the ChR_ChronoRay
backend + Tune restore). If a design is interrupted after 180 of its N tickets,
the whole design is an unfinished trial and re-runs all N tickets on resume --
the 180 completed inner sims are lost.

Sim-level resume means: on restart, a design skips the tickets it already
finished and only runs the remaining ones, then aggregates the full N.

WHETHER YOU NEED IT
-------------------
Only worth building if ONE design's inner loop (N sims across G GPUs) can
exceed a cluster wall-time window. That depends on your converged N (from the
Sobol study) and per-sim cost. If a design comfortably finishes inside a
window, design-level resume is enough -- skip all of this.


WHERE IT SLOTS IN
-----------------
The seam is already marked in ChRDispersionOpt._run_dispersion(). That method
currently:
    1. builds the N (design+ticket) configs,
    2. submits all N as Ray tasks,
    3. ray.get() -> list of N outputs (blocks on all N),
    4. returns them for objective_fn.

Sim-level resume changes step 1-3 into: load done tickets from disk, submit
only the pending ones, then combine loaded + newly-run into the full N.


WHAT TO REUSE FROM ChRDoE
-------------------------
ChRDoE already solved "skip already-done work on restart" -- reuse that pattern:
    - _config_hash(config)        : stable id from a config's values
    - _load_done_hashes()         : gather ids already logged (success + failure)
    - _log_success(...)           : append one record per completed unit
    - _log_failure(...)           : append one record per failed unit
The mechanism is identical; only the "unit" changes from a DoE config to a
(design, ticket) pair.


IMPLEMENTATION STEPS
--------------------
1. PERSIST EACH TICKET RESULT AS IT COMPLETES
   - Each inner unit is a (design, ticket) pair. Its stored record must include
     the ticket's RAW OUTPUT (not just "done"), because objective_fn needs the
     actual output values to aggregate -- unlike ChRDoE, which only needs "was
     this config run."
   - Key each record by a hash of (design values + ticket values), so a resumed
     design picks up ITS OWN partial results and never collides with a different
     design that happened to touch the same ticket.
   - Write as each task finishes. Switch step 3 from a single ray.get(futures)
     (waits for all) to a ray.wait() loop (returns them one at a time), logging
     each result the moment it lands so a kill preserves what finished.

2. SKIP DONE TICKETS ON ENTRY
   - At the top of _run_dispersion, for this design, load the already-logged
     ticket outputs. Submit Ray tasks ONLY for tickets not yet logged.

3. RECOMBINE INTO THE FULL N, IN TICKET ORDER
   - objective_fn expects the N outputs in ticket order. Merge loaded outputs
     with newly-run outputs back into the original ticket ordering before
     returning. (Track each output by its ticket index.)

4. STORAGE LOCATION
   - Put the per-ticket log under the SAME restorable storage path the backend
     uses (restore_experiment_storage_path), so design-level and ticket-level
     resume live together and survive on the cluster's shared filesystem.
   - Use a distinct file per experiment (like ChRDoE's results_prefix) so
     separate campaigns don't share logs.


GOTCHAS / DECISIONS
-------------------
- DETERMINISTIC TICKETS ARE REQUIRED. This only works because the N Sobol
  tickets are frozen with a fixed seed, so ticket i is the same on resume.
  Keep sobol_seed fixed and generate tickets once (already the case).

- DESIGN IDENTITY. Two different designs produce different scores from the same
  tickets, so records MUST be keyed on design values too, not ticket alone.
  (Bayesian designs are continuous floats -- hashing exact values is fine since
  the optimizer re-proposes the identical design on trial resume.)

- FAILED TICKETS. Currently a failed inner sim propagates and fails the whole
  design. Decide the policy: log failures and skip (like ChRDoE), or retry.
  This is a separate concern from resume but shares the same logging path.

- BLOCKING SEMANTICS UNCHANGED. Even with resume, the design still can't report
  its score until all N outputs exist (loaded + newly-run). objective_fn needs
  the complete set.

- INTERACTION WITH DESIGN-LEVEL RESUME. Backend/Tune still handles WHICH designs
  are done. Ticket-level resume only handles WHICH tickets within the current
  (unfinished) design are done. The two layers are complementary; ticket-level
  sits entirely inside _run_dispersion and needs no backend change.


MINIMAL CHANGE SURFACE
----------------------
Everything above lives inside ChRDispersionOpt:
    - add per-ticket log read/write helpers (adapt ChRDoE's four methods),
    - rework _run_dispersion step 1-3 (load -> submit pending -> ray.wait loop
      -> recombine),
    - add a results-prefix / storage constructor arg if you want it configurable.
No change to ChR_ChronoRay or the outer loop.
